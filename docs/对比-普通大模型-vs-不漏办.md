# 普通大模型对比：豆包 / DeepSeek / Kimi vs 不漏办

> 测试日期：2026-10-29
> 不漏办环境：真实 DeepSeek Flash（`mode=real`，`/health` 正常）
> 对比方式：同一段通知分别输入豆包、DeepSeek、Kimi 和「不漏办」；前三个只做一次普通对话，不使用工具、知识库或结构化约束。
> 目的：不是证明“我们一定更好”，而是找出普通大模型与结构化办事助手的差异，以及我们这次真实输出的问题。

## 1. 测试通知

```text
关于开展2026年校园创新挑战赛的通知

各学院：
请于下周三（11月5日）17:00前完成线上报名。参赛需准备以下材料：1. 项目申报书（需指导老师签字，一式三份）；2. 演示视频（MP4格式，限时3分钟）。请注意：大一新生需额外提交高考成绩单，大二及以上学生需提供上一学年成绩单。请各团队先将电子版申报书发至辅导员邮箱进行初审，初审通过后，方可录制并上传演示视频。若有省级以上获奖证书，请一并扫描上传（选填）。未按时提交者视为弃权。
```

## 3. 三个普通大模型的输出要点

### 3.1 豆包

- 把材料分成“项目申报书 / 成绩单（按年级二选一）/ 演示视频 / 选填证书”；
- 明确指出“初审通过之后再录制上传”；
- 把线上报名放在最后一步；
- 额外给出“需要我帮你改成打卡表格版吗”的交互建议；
- 没有原文出处，也没有结构化字段。

### 3.2 DeepSeek

- 用 8 个 checkbox 组织任务；
- 明确“确认团队成员年级”，再准备对应成绩单；
- 明确“先发电子版申报书初审，确认通过后再录视频”；
- 建议保存报名成功截图和提交记录；
- 没有原文出处，不能直接变成可勾选清单。

### 3.3 Kimi

- 按“准备 → 初审 → 初审通过后”三段组织；
- 正确写出成绩单按年级二选一、证书选填、视频在初审通过后录制；
- 额外增加“组建团队，确认参赛成员”，这条原文没有明确要求；
- 没有原文出处，不能直接导出/保存为任务。

## 5. 逐项分析

### 5.1 不漏办的优势

1. **结构化**：不是一段文字，而是 Matter JSON，可直接渲染材料/步骤/待办。
2. **可追溯**：每条材料、步骤、待办都能回到原文 `source_ref.quote`；普通模型只能给结论，不能给逐条依据。
3. **可执行**：12 条 todo 带 ID、状态，可勾选、保存、导出；普通模型要用户自己抄成清单。
4. **流程依赖**：step_3 依赖 step_2、step_4 依赖 step_3，正确表达“初审通过后才能录视频”。
5. **可降级**：真实模型失败仍能走 Mock/本地 OCR，普通模型没有工程级兜底。

### 5.2 修复记录与剩余不足

| 问题 | 影响 | 优先级 | 状态 |
| --- | --- | --- | --- |
| 条件材料没有 condition 字段 | 大一/大二两项成绩单同时显示为必交 | P0 | ✅ 已修，按 `grade` 过滤 |
| 选填证书被标为 required | 缺项核对多报一项，违背原文 | P0 | ✅ 已修，自动标 optional |
| 最终报名步骤排到第 1 步 | 用户按顺序执行会先报名后准备材料 | P0 | ✅ 已修，最终步骤最后并依赖前置 |
| “下周三（11月5日）”没有做星期一致性校验 | 11/5 实际是周四，所有模型都没指出 | P1 | ⏳ 未修 |
| 没有把“电子版/纸质版”作为材料属性 | 申报书“一式三份/电子版初审”只落在 todo 文案里 | P1 | ⏳ 未修 |

### 5.3 普通模型的不足

1. 没有 `source_ref`，无法逐条核验；
2. 输出是自然语言，不能直接被前端勾选、保存、导出；
3. 可能加入原文没有的任务（如 Kimi 的“组建团队”、DeepSeek 的“确认年级”属于合理推断但非原文明确要求）；
4. 没有工具调用、日期校验、缺项差集、版本历史；
5. 无法保证同样输入的结构稳定。

## 6. 这次对比的结论

- **普通模型更像“会总结的助手”**：读起来顺、顺序和条件通常更符合人类直觉，但不能直接执行、不能逐条溯源。
- **不漏办更像“能落地的清单引擎”**：P0 修复后，条件材料、选填证书、最终步骤顺序都已对齐；结构、出处、待办、依赖、导出仍是普通模型没有的。
- **仍不能把日期矛盾当成已解决**：“下周三”和“11月5日（周四）”的冲突目前没有提示；这是下一轮 P1，不应在演示中宣称“日期都能自动核对”。
