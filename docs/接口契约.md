# 接口契约（不得随意变更）

> 后端服务：`backend/main.py`（FastAPI）
> 抽取服务：`backend/service.py` → `analyze_notification(text)`

## 1. 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/health` | 服务自检：`{"status":"ok","mode":"mock"或"real"}` |
| `POST` | `/api/analyze` | 通知原文 → Matter JSON |
| `GET` | `/` | 服务信息（演示用） |
| `GET` | `/docs` | 自动生成的交互式接口文档 |
| `POST` | `/api/check` | 用户情况核对：返回还缺哪些材料、哪些需要确认（纯规则，不调模型）— 10/18 里程碑 |
| `POST` | `/api/analyze-image` | 图片（截图）→ Matter：`multipart/form-data`，字段 `image` — 10/23 里程碑 |
| `POST` | `/api/evidence` | 点一条要求 → 返回支持它的原文（无依据则标为系统建议）— 10/22 里程碑 |
| `POST` | `/api/analyze-pdf` | 文字型 PDF → Matter：`multipart/form-data`，字段 `file` — 10/25 里程碑 |
| `POST` | `/api/files` | 上传材料（TXT/MD/文字型 PDF）→ 切片段并编号 — 10/26 里程碑 |
| `POST` | `/api/ask` | 先检索材料再回答，附出处；材料外问题不乱答 — 10/27 里程碑 |
| `POST` | `/api/compare` | 两份通知分别保留来源并对比差异 — 10/28 |
| `POST` | `/api/prepare-list/save` | 用户确认后保存清单版本 — 10/29 |
| `GET` | `/api/prepare-list/{id}/history` | 查看最近 5 个修改前版本 — 10/29 |
| `GET` | `/api/tools/check-date` | 星期 / 距今 / 周末 / 节假日 — 10/30 |
| `GET` | `/api/prepare-list/{id}/export` | 导出 CSV / Markdown — 10/30 |
| `DELETE` | `/api/files/{id}` 等 | 按会话删除文件、清单、对比记录 — 11/06 提前完成 |

**响应约定：所有 `/api/analyze` 响应都是 HTTP 200 + 统一结构**，包括参数错误与内部异常 —— 前端只需判断 `success`，不用处理 FastAPI 默认的 422 `detail`。

```json
{ "success": true, "data": { "...": "Matter JSON" }, "error": null }
{ "success": false, "data": null, "error": "通知内容不能为空" }
```

## 2. POST /api/analyze

### 请求

```json
{ "text": "请于10月25日18:00前提交奖学金报名表。" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | string | 是 | 通知原文（纯文本） |

### 入口校验规则

| 情况 | `success` | `error` |
| --- | --- | --- |
| 空字符串 / 只有空白 / 未传 `text` | `false` | `通知内容不能为空` |
| 长度 > 上限（默认 3000 字符，`MAX_TEXT_LENGTH` 可配） | `false` | `通知过长，当前N字符，上限3000` |
| 请求体不是合法 JSON | `false` | `请求体格式错误，应为 {"text": "通知原文"}` |
| 服务内部异常 | `false` | `服务内部异常：...` |
| 正常 | `true` | `null` |

### 成功响应示例（simple）

```json
{
  "success": true,
  "error": null,
  "data": {
    "schema_version": "1.0",
    "id": "matter_12b1dcb2",
    "mode": "simple",
    "mode_source": "auto",
    "complexity_score": 0.2,
    "title": "提交奖学金报名表",
    "priority": "medium",
    "status": "not_started",
    "status_source": "auto",
    "timezone": "Asia/Shanghai",
    "created_at": "2026-10-16T17:34:15+08:00",
    "updated_at": "2026-10-16T17:34:15+08:00",
    "detected_features": ["has_deadline"],
    "enabled_sections": ["summary", "schedule", "source"],
    "deadline": {
      "scope": "overall",
      "label": "截止时间",
      "all_day": false,
      "due_at": "2026-10-25T18:00:00+08:00",
      "source_ref": { "quote": "请于10月25日18:00前提交" }
    },
    "reminders": [
      { "reminder_id": "rem_1", "offset_minutes": 120, "channels": ["app"], "enabled": true }
    ],
    "sources": [{ "quote": "请于10月25日18:00前提交", "page": null }]
  }
}
```

## 3. Matter 结构（按模式递增）

| 字段 | simple | standard | complex | 说明 |
| --- | :-: | :-: | :-: | --- |
| `schema_version` / `id` / `mode` / `mode_source` | ✅ | ✅ | ✅ | 元信息 |
| `complexity_score` / `detected_features` / `enabled_sections` | ✅ | ✅ | ✅ | 复杂度评分与启用区块 |
| `title` / `priority` / `status` / `status_source` / `timezone` | ✅ | ✅ | ✅ | 概要 |
| `target` / `category` | 可选 | 可选 | 可选 | 原文明确提到时才输出 |
| `deadline`（含 `due_at`） | ✅ | ✅ | ✅ | 截止时间；`start_at`/`end_at` 仅 complex |
| `reminders` | ✅ | ✅ | ✅ | 有 DDL 时输出一条（`offset_minutes=120`） |
| `sources` | ✅ | ✅ | ✅ | 原文出处聚合 |
| `default_location` / `key_points` | ❌ | ✅ | ✅ | 地点与要点 |
| `attachments` / `materials` | ❌ | ✅ | ✅ | 附件与材料清单（`material_id` 关联 `attachment_id`） |
| `step_list` | ❌ | ✅ | ✅ | 步骤（含 ID 数组形式的 materials / attachments） |
| `warning_list` | ❌ | 仅 `deadline_risk`/`missing_material` | ✅ | 风险预警 |
| `recurrence` / `permissions` / `audit_log` / `comments` | ❌ | ❌ | 可选 | 周期规则与治理信息 |
| 步骤级 `dependencies` / `review` / `owner` / `sub_step_list` 等 | ❌ | ❌ | ✅ | 依赖、审核、多角色、子步骤 |

**硬性约束**

- `simple` 模式**禁止**出现：`owner`、`assignees`、`participants`、`contact`、`default_location`、`key_points`、`attachments`、`materials`、`step_list`、`warning_list`、`permissions`、`audit_log`、`comments`、`recurrence`。
- 空数组 / 空对象一律省略；原文没有的字段一律省略（不输出 `null` 占位）。
- 不编造原文没有的地点、负责人、审核人、材料、附件。
- 关键字段带 `source_ref.quote` 作为原文溯源；时间统一 `ISO 8601 + 08:00`。

复杂度评分公式（服务端重算，不采信模型给的数值）：

```
score = 0.2*has_deadline + 0.1*has_multiple_reminders + 0.2*has_multiple_steps
      + 0.2*has_materials + 0.1*has_review + 0.1*has_dependencies
      + 0.1*has_recurrence + 0.1*has_sub_steps

判定（优先级从高到低）：
1. 检测到 has_sub_steps / has_review / has_dependencies → complex
2. score < 0.3 → simple
3. 0.3 ≤ score ≤ 0.6 → standard
4. score > 0.6 → complex
```

## 4. 调用示例

### curl

```bash
curl -X POST http://127.0.0.1:8000/api/analyze \
  -H "Content-Type: application/json" \
  -d "{\"text\":\"请于10月25日18:00前提交奖学金报名表。\"}"
```

### 前端（fetch）

```js
const res = await fetch("http://127.0.0.1:8000/api/analyze", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: noticeText }),
});
const { success, data, error } = await res.json();
if (!success) return showToast(error);
render(data);   // data.mode 决定渲染哪些区块
```

完整的可直接复用封装见 `backend/for-frontend/api.js`。

## 6. POST /api/check（用户情况核对 · 10/18 里程碑）

把「用户填写的情况」和「A 抽出的 Matter」放在一起核对，回答两个问题：**还缺什么**、**什么需要用户去确认**。
**纯规则比对（不调用大模型）**，不修改 `/api/analyze` 的任何字段。

### 请求

```json
{
  "matter": { "...": "上次 /api/analyze 的 data（推荐：不跑模型）" },
  "text": "通知原文（没传 matter 时用它先抽取一次）",
  "checked_material_ids": ["mat_1"],
  "profile": { "has_video": false },
  "profile_checks": []
}
```

- `matter` 与 `text` 至少传一个；两个都传时以 `matter` 为准。
- `checked_material_ids` 支持材料 ID 或材料名。
- `profile` 的键值由前端决定；内置规则见 `backend/requirement_checker.py` 的 `DEFAULT_PROFILE_CHECKS`，可用 `profile_checks` 覆盖。

### 响应（`data` 字段）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `matter` | object | 原样回显传入的 Matter JSON |
| `mode` | string | `simple` / `standard` / `complex` |
| `required_total` | int | 必交材料总数（已勾选 + 仍缺） |
| `checked` | array | 已勾选的材料明细 |
| `missing_required` | array | **仍缺的必交材料** |
| `missing_optional` | array | 未勾选的可选材料 |
| `unchecked_unspecified` | array | 原文未明确是否必交的材料 |
| `need_confirm` | array | 需要用户确认的信息（如未识别到截止时间） |
| `profile_issues` | array | 用户自述与原文要求的冲突 |
| `ready` | bool | 必交是否齐全（且无自述冲突） |
| `ready_ratio` | float | 完成比例，可直接做进度条 |
| `summary` | string | 一句话结论文案 |

### 错误情况（同样遵循统一契约）

| 情况 | 返回 |
| --- | --- |
| `matter` 与 `text` 都不传 | `{"success":false,"data":null,"error":"请提供通知原文（text）或已解析结果（matter）"}` |
| `matter` 不是对象 | `{"success":false,"data":null,"error":"请求体格式错误，…"}`（Pydantic 校验，统一契约） |
| `text` 超长 | 与 `/api/analyze` 相同：`通知过长，当前N字符，上限3000` |
| `text` 抽取失败 | 原样透传 `/api/analyze` 的错误 |

### 前端用法（`backend/for-frontend/api.js`）

```js
import { analyzeNotice, checkRequirements } from "@/api/notice";

const { ok, data } = await analyzeNotice(text);            // 第一次解析
const r = await checkRequirements({ matter: data, checkedMaterialIds: ["mat_1"], profile: { has_video: false } });
if (r.ok) renderChecklist(data, r.data);                   // r.data.missing_required / summary / ready_ratio
```

## 7. POST /api/analyze-image（图片解析 · 10/23 里程碑）

前端上传一张**清晰的文字截图**，后端校验后交给 OCR / 多模态解析，返回与 `/api/analyze` **完全相同的信封**。

### 请求

- `Content-Type: multipart/form-data`
- 字段名：`image`（单张）
- 允许格式：**JPG / JPEG、PNG、WEBP**
- 大小上限：**5 MB**
- 前端用 `FormData` 时**不要手动设置 Content-Type**（浏览器会自动带 boundary）

```js
const fd = new FormData();
fd.append("image", file);                 // 字段名固定为 image
const res = await fetch(`${API}/api/analyze-image`, { method: "POST", body: fd });
const { success, data, error } = await res.json();
```

```bash
curl -X POST http://127.0.0.1:8000/api/analyze-image -F "image=@shot.png"
```

### 限制查询（前端可用它做提示，避免前后端文案不一致）

`GET /api/analyze-image/limits` →

```json
{"success": true, "data": {"field": "image", "content_type": "multipart/form-data",
 "max_files": 1, "max_bytes": 5242880, "max_mb": 5.0, "formats": ["JPG", "PNG", "WEBP"]},
 "error": null}
```

### 错误文案（都是 `success:false`，可直接展示给用户）

| 情况 | error |
| --- | --- |
| 格式不支持 | `仅支持 JPG / PNG / WEBP 格式（收到：…）` |
| 超过大小 | `图片不能超过 5 MB（当前 X.X MB）` |
| 空文件 | `图片内容为空，请重新选择` |
| 没传 `image` 字段 | `请求体格式错误：请检查字段与类型（… multipart: image）` |
| 未装本地 OCR 且未配置 Key | `图片解析暂不可用：未配置 TEAM_LLM_API_KEY，且本地 OCR 未安装（pip install -r requirements-ocr.txt）` |
| 图片无文字 / 太模糊 | `图片解析失败：未识别到文字，请换一张更清晰的通知截图` |
| 识别失败 / 图片无字 | `图片识别失败：…` / `图片中未识别到有效文字，请换一张更清晰的通知截图` |
| 解析异常 | `图片解析异常：…` |


> **识别策略（10/23 更新）**：配置了 `TEAM_LLM_*` → 优先用视觉大模型；没有 Key → 自动用**本地 OCR（RapidOCR）**兜底，
> 因此无 Key 也能跑通「截图 → Matter」。本地 OCR 安装：`pip install -r requirements-ocr.txt`。

> 现状（10/21）：接口与校验已就绪，解析实现由 A 在 10/23 接入（`backend/image_analyzer.py` 的 `analyze_image_bytes`）。接入后前端无需改动。

## 8. POST /api/evidence（查看依据 · 10/22 里程碑）

点击页面上的**任意一条要求**（材料 / 步骤 / 待办 / 附件 / 截止时间 / 预警 / 要点），返回支持它的**原文片段**；
原文没有直接依据时，返回 `is_suggestion: true`，前端标成「系统建议」。

### 单条查询

```json
POST /api/evidence
{
  "matter": { "...": "/api/analyze 的 data" },
  "target_type": "material",
  "target_id": "mat_1"
}
```

`target_type` 可选：`material` / `step` / `todo` / `attachment` / `deadline` / `warning` / `key_point`

返回：

```json
{
  "success": true,
  "error": null,
  "data": {
    "found": true,
    "target_type": "material",
    "target_id": "mat_1",
    "title": "报名表",
    "quote": "报名时需上传项目申报书（见附件1…）",
    "source_ref": { "quote": "…" },
    "is_suggestion": false,
    "note": null
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `found` | 是否找到该条目（不存在时 `false`，`note` 给出提示） |
| `quote` | 原文引用；没有依据时为 `null` |
| `is_suggestion` | `true` = 系统建议，原文未直接给出依据（前端用黄色/浅色标识） |
| `note` | 给用户看的说明文案 |

### 批量索引（前端可预取，给每条要求挂「查看依据」按钮）

```json
POST /api/evidence/index
{ "matter": { "...": "..." } }
```

返回 `data.items[]`（每项字段同上）与 `data.total`、`data.suggestion_count`。

## 9. POST /api/analyze-pdf（PDF 文字提取 · 10/25 里程碑）

上传**文字型 PDF**（能复制出文字的那种），后端提取文字后走同一套抽取，返回与 `/api/analyze` 相同的信封。

### 请求

- `Content-Type: multipart/form-data`，字段名 **`file`**，单文件
- 格式：**仅 PDF**（`application/pdf`）
- 大小：**≤ 10 MB**
- 页数：**≤ 30 页**
- 提取上限：20000 字符（超出截断）

```js
const fd = new FormData();
fd.append("file", pdfFile);           // 字段名固定为 file
const res = await fetch(`${base}/api/analyze-pdf`, { method: "POST", body: fd });
const { success, data, error } = await res.json();
```

### 限制查询

`GET /api/analyze-pdf/limits` →

```json
{"success": true, "data": {"field": "file", "max_files": 1, "max_bytes": 10485760,
 "max_mb": 10.0, "max_pages": 30, "formats": ["PDF"],
 "note": "仅支持文字型 PDF（可复制文字）；扫描件请改用截图"}, "error": null}
```

### 支持范围与错误文案

| 情况 | error |
| --- | --- |
| 非 PDF | `仅支持 PDF 文件（收到：text/plain）` |
| 超过 10MB | `PDF 不能超过 10 MB（当前 X.X MB）` |
| 超过 30 页 | `PDF 页数过多（N 页），当前最多支持 30 页` |
| 扫描版 / 图片型（提取不到文字） | `未从 PDF 中提取到文字：这可能是扫描版 / 图片型 PDF。请改用清晰截图（图片解析）或直接粘贴文字。` |
| 加密 PDF | `PDF 已加密，请先解除密码后再上传` |
| 文件损坏 | `PDF 读取失败：文件可能已损坏` |

## 10. 文件片段索引与检索（10/26 里程碑）

多份材料 → 切片段并编号 → 按问题检索原文。

| 接口 | 说明 |
| --- | --- |
| `POST /api/files` | `multipart/form-data`，字段 `file`；TXT / MD / 文字型 PDF；≤10MB；返回 `file_id` 与 `chunk_count` |
| `GET /api/files` | 已上传材料列表（不含全文） |
| `GET /api/files/{file_id}` | 文件详情 + 片段（每段带 `chunk_id`、`char_start/char_end`） |
| `GET /api/files/limits` | 支持格式与大小限制 |
| `POST /api/files/search` | `{"query":"视频时长","file_ids":["file_x"],"top_k":5}` → 相关片段 + 分数 |

片段编号规则：`file_ab12cd34_c1`、`_c2`…，检索结果可直接定位到"哪份文件、第几段"。

## 11. 追问接口（10/27 里程碑）

```json
POST /api/ask
{ "question": "视频有什么要求？", "file_ids": ["file_ab12cd34"], "matter": { } }
```

返回：

```json
{
  "success": true,
  "data": {
    "answer": "根据原文：「作品演示视频不超过3分钟…」（出处：视频要求.md / file_x_c1）",
    "sources": [{"file_id": "file_x", "filename": "视频要求.md", "chunk_id": "file_x_c1", "quote": "…", "score": 0.33}],
    "mode": "retrieval"
  },
  "error": null
}
```

- 有可用大模型 Key → `mode: "llm"`（调用 `service.ask_question`）
- 无 Key → `mode: "retrieval"`（直接返回最相关原文，附出处）
- **材料里找不到依据** → `answer: "在已上传的材料中没有找到与这个问题相关的原文，无法回答。"`、`sources: []`，不编造

## 12. 多用户会话隔离（11/06 提前完成）

除健康检查外，涉及用户数据的接口统一读取请求头：

```http
X-Session-Id: user_ab12cd34
```

- 同一浏览器应持久化一个随机 `session_id`，后续上传、保存、读取、删除都带同一个值。
- 不传时回落为 `default`，旧前端仍可工作；但比赛演示建议显式传入。
- 文件库、准备清单、通知对比均按会话隔离；不同会话不能互相读取或删除。
- 新增删除接口：
  - `DELETE /api/files/{file_id}`
  - `DELETE /api/prepare-list/{matter_id}`
  - `DELETE /api/compare/{comparison_id}`

## 13. POST /api/compare（双通知对比 · 10/28）

同一事项的两份通知分别解析，保留各自文件名、原文和 Matter 结果，再返回差异。

```json
POST /api/compare
{
  "left":  { "filename": "旧版通知.txt", "text": "11月2日17:00前提交报名表和成绩单" },
  "right": { "filename": "新版通知.txt", "text": "11月3日18:00前提交报名表、成绩单和身份证复印件" }
}
```

每侧也可传 `matter` 代替 `text`。响应 `data`：

| 字段 | 说明 |
| --- | --- |
| `comparison_id` | 对比记录 ID |
| `left` / `right` | 文件名、`source_ref`、原文、完整 Matter |
| `diff.deadline` | 两侧截止时间及 `changed` |
| `diff.materials` | `common` / `only_left` / `only_right` / `changed` |
| `diff.steps` | `common` / `only_left` / `only_right` / `changed` |
| `diff.has_difference` | 是否存在任何差异 |

记录接口：`GET /api/compare`、`GET /api/compare/{id}`、`DELETE /api/compare/{id}`。

## 14. 准备清单版本、导出与删除（10/29–10/30）

## 16. 调用限流与密钥安全（10/31）

- 真实模型模式自动启用内存滑动窗口限流；Mock 联调默认关闭。
- 普通模型接口默认 `60 次/分钟/IP`，上传类接口默认 `10 次/分钟/IP`。
- 可通过 `RATE_LIMIT_PER_MINUTE`、`UPLOAD_RATE_LIMIT_PER_MINUTE` 调整。
- 超限仍按统一信封返回 `{"success":false,"data":null,"error":"请求过于频繁…"}`，并带 `Retry-After` 响应头。
- API Key 只从环境变量 / `.env` 读取；`.env` 已被 `.gitignore` 排除，禁止提交。
