# 演示视频脚本（5–8 分钟 · 1080p）

> 比赛要求：5–8 分钟，MP4，≥1080p，普通话讲解，内容含项目介绍 / 核心功能演示 / AI 技术亮点。
> 本脚本按 **7 分钟** 写，录屏 + 口播即可；括号内是操作提示，不用念。

## 0:00–0:40 开场（40s）

**画面**：项目首页（三栏布局），鼠标缓慢划过输入框、结果区、任务清单。

**口播**：
> 大家好，我们是 Triple Y。我们做的是「通知抽取助手」。
> 校园里的通知散落在群消息、公告和截图里：截止时间藏在一句话里，材料清单夹在正文中，步骤还要自己理。
> 我们做的事情很简单：粘贴一段通知，AI 把它变成一份可以照着做的清单。

## 0:40–1:50 核心流程：粘贴 → 结构化（70s）

**画面**：粘贴一条标准通知 → 点「AI 智能解析」→ 结果卡片出现。

示例文本：
```
奖学金报名：10月25日18:00前提交报名表（附件1）、成绩单、身份证复印件，交至行政楼302，需本人签字。
```

**口播**：
> 粘贴原文，点分析。系统自动判断通知复杂度，选择三档结构之一：极简、标准、完整流程。
> 这条属于标准模式：它提取了截止时间、地点、注意事项、两条办理步骤和三份材料，每一条都带原文出处。

**画面**：指着 mode 徽章、截止倒计时、材料清单。

## 1:50–3:00 用户情况 → 缺什么（70s）

**画面**：在「我们队的情况」勾选报名表、演示视频选"没有"、老师签字选"需要" → 点「提交核对」。

**口播**：
> 光有清单还不够，用户需要知道"我还缺什么"。
> 勾选已经准备好的材料，再填一下团队情况。系统会分三类告诉你：已准备、缺少、需要确认。
> 比如这里，它会直接指出：还缺成绩单和身份证复印件；视频没有准备，也会被单独提示。

**画面**：三类结果 + 顶部结论句。

## 3:00–3:50 每条要求都能看到依据（50s）

**画面**：点击材料/步骤后的「出处」→ 弹出原文片段；再点一条系统建议 → 黄色「系统建议（无原文依据）」。

**口播**：
> 大模型最让人不放心的是"会不会编"。
> 所以每一条要求都能点开看依据：有原文的，直接给出原文片段；没有依据的，会明确标成"系统建议"，而不是假装有出处。

## 3:50–4:50 截图和 PDF 也能解析（60s）

**画面**：上传一张通知截图 → 预览 → 分析 → 结果；再上传一份文字型 PDF → 分析。

**口播**：
> 现场拿到的往往是截图或者 PDF。
> 截图会先做文字识别，再走同一套抽取；PDF 会先提取文字。扫描版 PDF 会明确提示改用截图，而不是给一个空结果。

## 4:50–5:40 材料内追问，答不出来就说不知道（50s）

**画面**：上传两份材料 → 在追问框问「视频有什么要求？」→ 回答 + 出处；再问「食堂几点开门？」→ 提示未找到。

**口播**：
> 我们还做了一个"只根据材料回答"的追问入口。
> 先检索材料片段，再回答，并且附上出处；问题超出材料范围时，它会直接说没有找到依据，不编造。

## 5:40–6:40 AI 技术亮点（60s）

**画面**：切到架构图（或 `/docs` 页面 + 代码片段）。

**口播**：
> 技术上我们做了四件事：
> 第一，复杂度不是模型说了算，而是用固定公式重算，再按规则裁剪字段，保证输出稳定可复现；
> 第二，输出有 JSON Schema 校验和字段互斥约束，simple 模式不会跑出材料和步骤；
> 第三，模型不可用时有一整条降级链路：视觉模型不可用走本地 OCR，没有 Key 走离线 Mock，前端始终有结果可看；
> 第四，RAG 检索先查材料再回答，答不出来就明说，避免幻觉。

## 6:40–7:00 收尾（20s）

**画面**：回到首页 + 仓库地址。

**口播**：
> 一句话：把通知变成能执行、能核对、能追责的清单。代码和文档都在 GitHub，谢谢观看。
