# 用户测试工具包（A 侧）

> 状态：**工具已准备，真人测试尚未执行**。  
> 不能由代码或 AI 代替真实用户；本目录用于团队在 2026-11-14 前完成 8–10 名同学测试后直接汇总。

## 1. 测试目标

验证「不漏办」是否真的减少“漏材料、看错截止时间、不知道下一步”：

- 用户能否在 3 分钟内完成一次通知解析；
- 用户能否正确说出截止时间、必交材料、第一步动作；
- 用户是否能发现“查看依据”和“缺少材料”；
- 补充通知改期后，用户能否确认更新而不是被静默覆盖；
- 出错时用户是否知道下一步（对应评审意见“错误处理再友好些”）。

## 2. 样本与伦理

- 8–10 名在校学生（大一/大二/大三均可），不使用真实身份证号、手机号、成绩单原件。
- 使用 `docs/demo-kit/` 和 `docs/eval-v2/assets/` 中的虚构通知。
- 开始前口头说明：只记录操作与耗时，不收集账号密码；可随时退出。
- 不录屏人脸；如录屏只录浏览器窗口。

## 3. 测试流程（每人 15 分钟）

1. 30 秒介绍：这是办事清单工具，不是聊天机器人。
2. 任务 A：粘贴 `01-标准通知-奖学金.txt` → 解析 → 说出截止时间/材料/第一步。
3. 任务 B：上传 `04-通知截图.png` → 解析 → 查看一条“出处”。
4. 任务 C：用 `06` + `07` 做补充通知对比 → 确认更新。
5. 任务 D（错误场景）：断开后端或上传不支持格式 → 观察提示，问“你知道下一步做什么吗？”
6. 记录 `记录表.csv`，并让用户用 1–5 分评价“是否愿意继续使用”。

## 4. 指标

| 指标 | 计算 |
| --- | --- |
| 任务完成率 | 完成任务人数 / 总人数 |
| 平均完成时间 | 各任务从开始到说出结果的秒数 |
| 关键信息正确率 | 截止时间/材料/第一步答对人数 / 总人数 |
| 错误恢复率 | 错误场景中能说出下一步的人数 / 总人数 |
| 易用性评分 | 1–5 分均值 |
| Top 问题 | 按出现频次排序，至少闭环 3 个 |

## 5. 汇总

```powershell
backend\.venv\Scripts\python.exe scripts\summarize_user_test.py docs\用户测试\记录表.csv
```

输出：人数、任务完成率、平均耗时、易用性均值、错误恢复率、Top 问题。  
把结果写入技术文档 6.2 / 8.3，不要编造未执行的数字。
