## 3. 本次修复

1. **模式误判**：模型把“指导老师签字”误判成 `has_review`，把并列步骤误判成 `has_dependencies`，导致 03 被升级为 complex。
   - 修复：`sanitize_features` 用原文关键词校验；complex 必须有原文依据；`recompute_complexity` 保留 3 位小数。
   - 结果：03 从 complex → **standard**。
2. **补充通知误删材料**：补充通知只新增推荐表、没有重复列原材料时，A 侧原逻辑会把 3 项原材料误报为“删除”。
   - 修复：补充通知默认按增量处理；只有明确“取消/不再要求/改为”且点名材料时才删除/替换。
   - 结果：06+07 无误删，原材料保留，新增推荐表正常。
3. **待办/确认项**：A 侧对比现在输出受影响待办（更新截止、新增待办、需确认删除），不再把“没重复列”当成“删除”。
4. **截图日期非 ISO**：视觉模型返回“11月2日 17:00”，前端倒计时和日期工具无法直接解析。
   - 修复：新增 `_normalize_deadline_value`，中文月日自动补当前年份并转 ISO。
   - 结果：截图 deadline 变为 `2026-11-02T17:00:00+08:00`。
5. **simple 模式出现 `warning_list`**：`MatterExtractor` 裁剪后，service 又追加了 warning；已加 `_apply_mode_guards`，在补字段后再按 mode 裁剪一次。
   - 结果：纯 simple 样本无 `warning_list`、无 materials/step_list。
6. **step_list[].order 重复**：真实模型返回 `[1,1]` / `[1,1,1,1]`；新增 `normalize_step_orders`，统一重排为 1..N（子步骤同理）。
   - 结果：样本2 `[1,2]`，样本3 `[1,2,3,4]`。
7. **结构验收样本1期望值**：原样本含“提交报名表”，按公式是 standard；已把 simple 样本改成“请于10月25日18:00前完成报名”，保证三档验收覆盖 simple/standard/complex。
