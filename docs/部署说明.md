# 部署与在线演示说明（C）

> 对应比赛可选加分项「在线演示」：提供可公网访问的地址，评审期间保持可用。

## 1. 本地运行（开发/演示）

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
# 前端
cd ..\frontend
npm install
npm run dev
```

- 后端健康检查：<http://127.0.0.1:8000/health>
- 接口文档：<http://127.0.0.1:8000/docs>

## 2. Docker 部署（推荐给服务器）

前提：服务器装好 Docker（含 compose 插件）。

```bash
# 1) 拉代码
git clone https://github.com/sssweetis/chuanzhi-cup-ai-web_Triple-Y.git
cd chuanzhi-cup-ai-web_Triple-Y

# 2) 准备配置（不要提交）
cp backend/.env.example backend/.env
# 编辑 backend/.env：LLM_ENABLE_MOCK / LLM_API_KEY / LLM_BASE_URL / LLM_MODEL
#                 TEAM_LLM_*（截图视觉模型，可选）

# 3) 启动
docker compose up -d --build

# 4) 验证
curl http://127.0.0.1:8000/health
```

- 镜像里已包含：FastAPI + uvicorn、pypdf（PDF）、RapidOCR + onnxruntime（本地 OCR 兜底）
- `backend/data/` 通过 volume 持久化（准备清单、文件片段索引）
- 容器内自带 HEALTHCHECK（30s 一次 /health）

## 3. Nginx 反向代理 + HTTPS（公网演示）

```nginx
server {
    listen 80;
    server_name demo.example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 180s;   # 真实模型解析可能要 10~30s，PDF/OCR 更久
        client_max_body_size 12m;  # 后端限制 PDF 10MB，这里留余量
    }

    location /health {
        proxy_pass http://127.0.0.1:8000/health;
    }

    # 前端静态文件（npm run build 产物）
    location / {
        root /var/www/tripley;
        try_files $uri $uri/ /index.html;
    }
}
```

> HTTPS 用 certbot：`certbot --nginx -d demo.example.com`

前端构建：

```bash
cd frontend
# 线上后端地址：在 .env.production 里写 VITE_API_BASE_URL=https://demo.example.com
npm run build      # 产物在 frontend/dist，上传到 /var/www/tripley
```

## 4. 部署检查清单

- [ ] `/health` 返回 `{"status":"ok","mode":"real"或"mock"}`
- [ ] `/docs` 能打开
- [ ] CORS 正常（前端域名能调 `/api/analyze`）
- [ ] `backend/.env` 不在 git 里（`git status` 看不到）
- [ ] 上传接口可用（图片 ≤5MB / PDF ≤10MB）
- [ ] 容器重启后数据还在（`docker compose restart` 后 GET 准备清单）
- [ ] 演示前把 `LLM_ENABLE_MOCK=0` 且 Key 可用（或明确标注 mock）

## 5. 无公网服务器时的替代方案

1. **内网穿透**：`cloudflared tunnel --url http://127.0.0.1:8000`（临时地址，演示够用）
2. **校园网 + Radmin VPN**：评审需要装客户端，不推荐给评委
3. 只提交演示视频 + 本地可运行仓库（在线演示是加分项，不是必需）
## 6. 上线前的密钥与限流检查

- 在部署平台（Render / 服务器）的环境变量里填 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`，不要提交 `.env`。
- 真实模式默认开启限流：普通接口 60 次/分钟，上传接口 10 次/分钟，可通过环境变量调整。
- 前端请求带稳定的 `X-Session-Id`；文件、准备清单、对比记录按会话隔离。
- 部署完成后把公网地址写进交付说明，并按 11/01 清单逐项验证上传、保存、下载和错误提示。

## 7. Render 上线步骤（海外平台，可选，不推荐国内团队）

1. 用团队 GitHub 账号登录 <https://render.com>。
2. 选择 **New → Blueprint**，连接仓库 `sssweetis/chuanzhi-cup-ai-web_Triple-Y`。
3. 选择 `main` 分支，Render 会读取根目录的 `render.yaml`。
4. 首次部署时先保持：
   - `LLM_ENABLE_MOCK=1`
   - `LLM_API_KEY` 留空
5. 点击 Apply / Deploy，等待 Docker 构建完成。
6. 打开部署生成的 `https://<服务名>.onrender.com/health`，应看到：
   ```json
   {"status":"ok","mode":"mock"}
   ```
7. 把真实公网地址填入 README / 提交说明，并执行：
   ```powershell
   cd <????>
   powershell -ExecutionPolicy Bypass -File .\scripts\online_acceptance.ps1 -BaseUrl https://<服务名>.onrender.com
   ```
8. 拿到团队 Key 后，在 Render 的 **Environment** 中填：
   - `LLM_ENABLE_MOCK=0`
   - `LLM_API_KEY`
   - `LLM_BASE_URL`
   - `LLM_MODEL`
   - 可选的 `TEAM_LLM_*`
   保存后重新部署，`/health` 应变成 `real`。

### Render 免费实例注意事项

- 免费实例长时间无人访问后会冷启动，第一次请求可能需要 30–90 秒；演示前先打开一次 `/health` 预热。
- 免费实例的本地磁盘是临时的：重新部署、重启或实例迁移后，`backend/data/` 中的上传文件和保存清单可能清空。演示前重新上传即可。
- 如果要长期保存数据，需要给 Render 配置持久磁盘，或改用带 volume 的服务器 Docker；当前 `docker-compose.yml` 已支持 volume。
- 清理演示数据只在本地 `backend/data/` 生效，不会自动清理线上数据；线上可以在页面的删除按钮按会话清理。
- `.env` 和 Key 只能放在 Render Environment，不要提交到 GitHub。

## 8. 国内云服务器部署（推荐最终方案）

### 推荐配置

- 腾讯云轻量应用服务器 / 阿里云轻量应用服务器
- 地域：离团队较近的国内地域
- 系统：Ubuntu 22.04 或 Ubuntu 24.04
- 配置：**2 核 4 GB** 起；OCR 和 Docker 构建比普通静态站更吃内存
- 公网 IPv4：必须有
- 防火墙放行：`22`（SSH）、`80`（HTTP）；需要 HTTPS 时再放行 `443`
- 预算：以平台当期学生优惠为准，一般按月购买，演示结束后可退订或降配

> 不建议用 1 核 1 GB 或 2 GB 小内存实例，Docker 构建 RapidOCR 依赖时容易内存不足。

### 第一步：购买并登录服务器

购买时如果应用模板里有 **Docker CE**，优先直接选择。
登录后确认：

```bash
docker --version
docker compose version
```

如果提示 `permission denied`：

```bash
sudo usermod -aG docker $USER
# 退出 SSH，再重新登录
```

### 第二步：下载项目

```bash
git clone https://github.com/sssweetis/chuanzhi-cup-ai-web_Triple-Y.git
cd chuanzhi-cup-ai-web_Triple-Y
```

### 第三步：配置环境变量

```bash
cp backend/.env.example backend/.env
nano backend/.env
```

先做 Mock 演示时：

```env
LLM_ENABLE_MOCK=1
LLM_API_KEY=
PORT=8000
MAX_TEXT_LENGTH=10000
RATE_LIMIT_PER_MINUTE=60
UPLOAD_RATE_LIMIT_PER_MINUTE=10
```

拿到团队 Key 后再改成：

```env
LLM_ENABLE_MOCK=0
LLM_API_KEY=<团队Key>
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

不要把 `backend/.env` 提交或发给评委。

### 第四步：一键构建并启动

```bash
bash scripts/deploy-vps.sh
```

脚本会启动：

- `tripley-backend`：FastAPI，仅 Docker 内网访问 8000
- `tripley-web`：Nginx + 构建后的前端，公网监听 80
- Nginx 将 `/api/`、`/health`、`/docs` 转发给后端
- `backend/data` 挂载为 volume，容器重建后数据仍保留

### 第五步：验证

浏览器打开：

```text
http://服务器公网IP/
http://服务器公网IP/health
http://服务器公网IP/docs
```

`/health` 是 Mock 时应显示：

```json
{"status":"ok","mode":"mock"}
```

配置真实 Key 后应显示：

```json
{"status":"ok","mode":"real"}
```

然后在本地运行线上验收：

```powershell
cd <????>
powershell -ExecutionPolicy Bypass -File .\scripts\online_acceptance.ps1 -BaseUrl http://服务器公网IP
```

### 常用运维命令

```bash
# 查看状态
docker compose -f docker-compose.prod.yml ps

# 查看日志
docker compose -f docker-compose.prod.yml logs --tail=200

# 更新代码
git pull --ff-only
docker compose -f docker-compose.prod.yml up -d --build

# 重启
docker compose -f docker-compose.prod.yml restart

# 停止
docker compose -f docker-compose.prod.yml down
```

### 数据与清理

- 文件库、准备清单、通知对比存放在服务器 `backend/data/`。
- `docker compose down` 不会删除 volume；`down -v` 才会删除数据卷。
- 演示前可在服务器执行：
  ```bash
  cd backend
  python reset_demo_data.py
  ```
  需要宿主装有 Python；没有 Python 时也可以在页面中按会话删除数据。
- 重新部署不会自动清空 `backend/data/`。

### 域名与 HTTPS（可选）

只提交公网 IP 和 HTTP 地址也能满足“可公网访问”。
如果团队有国内备案域名，再把域名解析到服务器 IP，并在 Nginx 上配置 HTTPS；没有域名时不要为了比赛临时折腾备案。
